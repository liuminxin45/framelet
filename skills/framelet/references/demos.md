# Product demonstrations / 产品演示

Choose a short, concrete interaction that demonstrates the user's intended feature. Select the visible app region, keep readable text at original size when practical, and use the current presentation guidance (normally 30 FPS). Use a short trial when performance is uncertain; do not promise target FPS as measured throughput.

Record first, await readiness, operate the target app, then stop and await save. For long sessions use one named rotating group so segment names retain task identity; never construct unrelated single-GIF filenames as an imitation of rotation.

Find motion/action candidates, batch-probe boundaries, and retain enough opening and closing context to understand the transition. Send a limited contact sheet before individual images. Review the actual result in a suitable viewer; GIF browser timing may differ at short frame delays. Keep source media and publish a separate derived output. Return dimensions, duration, file size and any sampling compromise relevant to the demo.
