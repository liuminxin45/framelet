# Product demonstrations / 产品演示

For a human-facing demo, explicitly choose 30 FPS, including README GIFs. Lower FPS is a deliberate size/performance compromise that must be reported; README placement alone does not justify 12 FPS. Inspect measured sampling during action intervals, not encoded GIF frames or just whole-recording averages.

Prepare the app and plan before capture. Start → await ready → perform the intended business interactions → wait for the intended result to settle → stop immediately → await terminal save. Keep unrelated screenshots/analysis/model deliberation outside capture. Use the host's existing desktop/browser tools; Framelet does not execute UI actions.

Real input events are natural anchors. If intent needs an explicit boundary, use the context-discovered marker tool for begin/end/point with a unique request_id. It never clicks the app. A queued receipt is not a recorded anchor: inspect recording_status.markers for state=recorded, its observation ID and native UTC/monotonic timestamps. Reusing identical request_id is safe during the active session; a conflict fails. Markers require ready, unpaused capture; limits are 64 per recording / 8 outstanding. Never manufacture high-frequency clicks or keys as anchors. A click is not its UI response; place end only after the intended result settles.

After save, use prepare_demo to analyze and save a separate trimmed candidate, or analyze once and edit a visually reviewed explicit range. These operations preserve raw media. Analyze combines 16px spatial RGB differences, real input and explicit markers; output includes quality findings, holds, action-window sampling and a suggested range. Unpaired/unmapped markers refuse automatic preparation. For a series, analyze the group and choose one committed part; a marked interval crossing parts needs an explicit reviewed part range. Internal waits remain intact because loading, reading or a defect may be the point of the demo.

Before delivering a demo, batch-probe the opening, every main action and closing result. Review a contact sheet and the actual GIF with an available viewer. A uniform three-point probe can miss the entire action. Resolve quality findings or explain intentional pauses. If motion was under-sampled, re-record with suitable region/FPS; trimming or duplicate frames cannot reconstruct it. Saved/candidate_saved never means visually approved. Return candidate and raw paths, dimensions, duration, size, measured sampling limitations and outstanding findings. Do not claim playback review when only frames were inspected.

If any step fails, inspect saved paths, terminal state, marker receipts and warnings before retrying. A cancelled wait does not stop recording. Stop saves; cancel discards unfinished single media. Disconnect cancels unfinished single capture unless stop was already accepted; groups preserve valid parts/checkpoints. Unconfirmed markers may not exist in the trace. Recover only after the owner exits; never repeat UI input automatically. An existing candidate is preserved and a same-output retry is refused: inspect/recover it or choose a distinct output.
