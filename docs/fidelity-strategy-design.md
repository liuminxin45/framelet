# 清晰度策略设计：像素、颜色、时间

状态：待审阅方案。基于 2026-11-02 的 Framelet；本文三组独立控制、预设及新 API 尚未实现。60 FPS 上限是本轮另行实施的能力，不代表这些策略已经上线。200 FPS 已取消，不纳入本方案。

## 1. 产品合约

把清晰度拆成三组可组合的控制，不提供含义模糊的“画质百分比”。日常只选 test / demo / compact / precision，专业用户和 AI 才覆盖具体参数。

- 像素决定文字/图形有多少真实细节；颜色决定渐变、色块和对比的还原；时间决定哪些瞬间被保留。
- 保持原像素尺寸时，优先合并重复画面、压缩变化区域、稳定调色板，再考虑降低色数。只有显式选择缩放或 compact 才缩小；绝不默认缩小再放大。
- 裁剪时间、改变速度是独立编辑操作。降低输出帧率不能隐式缩短/延长录像。
- 录制参数、最终解析配置和实际结果都可查询，软件不能把请求参数当成实际达到的质量。
- PNG 截图适合像素级检查；GIF 即便原尺寸、256 色，也不能保证任意全彩画面无损。

## 2. 四个预设的建议默认值

| 预设 | 场景 | 像素 | 采集 / GIF 目标 FPS | 色数上限 | 抖动 | 调色板 |
| --- | --- | --- | --- | --- | --- | --- |
| test | 稳定状态、表单、软件验收 | 原尺寸 | 1 / 1 | 256 | 关闭 | 稳定，场景变化时更新 |
| demo | 软件演示、滚动、拖拽 | 原尺寸 | 30 / 30 | 256 | 关闭 | 稳定，场景变化时更新 |
| compact | README、聊天分享、文件大小优先 | 最长边 960，不放大 | 12 / 12 | 128 | 弱有序抖动，强度 0.2 | 稳定，场景变化时更新 |
| precision | 快速瞬态、动画和逐帧精查 | 原尺寸 | 60 / 60 | 256 | 关闭 | 稳定，优先检测颜色失真 |

以上是待视觉/性能测试的产品起点，不是已经校准的最优值。test 的 1 FPS 可能漏掉短暂状态；AI 关心瞬态时应覆盖为更高采集帧率。precision 的 60 FPS GIF 含短延时，浏览器播放可能变慢；面向分享选 demo，或显式覆盖输出为 30 FPS。60/30 只保留部分源画面，不能用于事后恢复全部 60 FPS 细节。

新清晰度接口未指定 preset 时统一采用 demo。相同 preset 可以用于单 GIF 和分段录制，不为两者维护不同默认。

## 3. 像素控制

建议统一为 size 对象，三种模式互斥：

| mode | 参数 | 规则 |
| --- | --- | --- |
| native | 无 | 输出与源录制区域像素一一对应；忽略无效缩放操作并明确提示 |
| fit | max_width、max_height，可只给一个 | 等比例放入边界框，禁止放大；两个值是边界，不代表强制拉伸成该矩形 |
| scale | factor，0 < factor ≤ 1 | 显式等比例缩小，确定性计算整数宽高，每边至少 1 像素 |

输出始终是固定像素画布。窗口布局、显示器 DPI、录制区域和输出尺寸分别记录；改变 DPI 标签不会增加真实细节。若未来需要固定画布补边，必须另加明确的 padding 模式及坐标偏移，不复用 fit 偷偷补边/拉伸。

缩放算法：

- area：默认缩小算法，按真实像素覆盖面积加权，处理非整数缩放比；适合减少混叠，但不能保证小字缩小后仍清楚。
- lanczos3：高级选项，适合图片/图形；评估边缘振铃，不能预设它总优于 area。
- nearest：仅适用于像素画和显式逐像素需求；不作为普通软件界面的默认。
- 原尺寸：跳过重采样，保留几何细节。resize_filter 的配置仍可记录为未应用，不能显示成真的处理过。

掩码在任何缩放、训练、预览和持久化之前应用。映射记录 source_region、output_size、scale_x/scale_y；键鼠位置保留源物理像素坐标，查询时另给 GIF 坐标，不覆盖原始位置。整数取整造成的两个比例按实际结果保存。

尺寸在录制前解析、校验并冻结。分段模式也不自动改变尺寸；显式重新配置应开启新段，保存 configuration_revision 和新映射。

## 4. 颜色控制

建议参数：colors=32/64/128/256，dither=off/ordered，dither_strength=0..1，palette_mode=stable/frame。

colors 表示调色板容量上限，非必须填满。透明色/掩码保留色若启用，应计入同一容量预算。默认沿用不透明变化矩形，避免为不需要的透明色白白损失可用颜色。相同尺寸减少颜色未必总能得到更小文件，结果必须实测。

### 稳定调色板与场景变化

当前 from_rgb_speed 会独立量化帧/变化矩形。新实现应改为“统一训练与映射 → indexed pixels → GIF 编码”，不把 quality 参数当成可控色数。

默认 stable 采用有明确编号的 palette epoch：

1. 第一张已遮挡、已缩放的完整画面，使用有界颜色统计训练初始表；立即编码，不等待整段结束，也不缓存数百张原始帧。
2. 对出现不超过 colors 种颜色的简单画面，优先精确映射。超过上限时采用确定性的量化；基线可用加权直方图/中位切分，并在开发样本上比较现有量化器。
3. 优先覆盖文字边缘、主要前景/背景和高频颜色，掩码纯色按需精确保留；不能承诺复杂场景所有文字颜色都无损。
4. 同一 epoch 冻结颜色表和映射规则，避免几乎相同的画面不断更换近似颜色。
5. 新场景持续无法被当前表表达时，创建新 epoch 并输出完整关键画面。短时颜色波动用门限、连续观测和最小更新间隔抑制，防止反复重建。门限需用测试校准，不在方案里伪造精确最佳值。
6. GIF 只有一个全局表；新 epoch 可通过局部表表达。局部表只作用于当前图像，后续帧使用该 epoch 时也需正确声明，不能把局部表当作自动持续生效。
7. 换表时不能比较前后颜色索引是否相同来判断画面变化：同一索引可能已指向不同颜色。必须按实际显示颜色和完整画布验证。

第一阶段在每个 GIF 段独立建立稳定表。段边界颜色可能轻微改变，需在验收中明确测量；跨段继承/按需换表可作为后续优化，不能以降低新场景还原为代价强行复用。

frame 模式保留逐帧自适应能力，适用于颜色变化复杂的内容，明确提示可能闪烁且表开销更大，不作为四个预设的默认。

### 抖动与变化区域

默认关闭抖动，优先保护文字边缘和静态稳定性。有序抖动使用固定矩阵、固定输出画布原点与确定性强度；变化矩形裁剪不能重置图案原点，避免静止区域“爬动”。本阶段不默认使用随机或跨帧误差扩散。

处理顺序必须先量化/抖动成最终显示颜色，再计算变化矩形；否则全局颜色表更新或抖动可能使裁剪外区域也变化。静止源可复用已有显示结果；完全相同画面合并延时，不删除键鼠记录。源画面发生变化但被量化抹平时，要能在质量报告/来源映射中区分，不能声称原始像素相同。

## 5. 时间控制与身份准确性

建议 capture_fps 与 gif_fps 分开，第一阶段均为整数 1–60，gif_fps ≤ capture_fps。它们是目标采样/输出调度频率，不是物理显示刷新率或合并后 GIF 帧数。

- 按单调时钟持续采集，记录真实开始/结束区间和原始观察 ID。低输出帧率不会降低键鼠观察精度。
- 输出按时间桶选择源画面，基线采用桶起点附近已采到的最近画面，使用有界等待；不得使用尚未采集的“未来画面”。
- 保留实际媒体时间；30 FPS 使用 30/30/40 毫秒等累计误差分配，60 FPS 使用 10/20 毫秒混合。只对输出时间轴做厘秒量化，原始 UTC/单调时间不取整。
- 相同画面合并后编码帧数可低于 gif_fps。不能据此判定采集丢帧，也不能用重复帧伪装采集达到目标。
- 暂停不进入媒体时间，检查点不消费仍在等待正常采样点的源帧。轮转准确切分媒体时长，不清零来源身份。
- event-aware 选择作为第二阶段能力：在同一时间桶内优先选择点击后/按键后的候选画面，仍受输出预算限制；不能保证每个输入事件都有独立画面，不能无提示增加 FPS 或改变时长。

### 时间线 schema 3 建议

采集帧率高于输出帧率后，当前 samples 不能再同时承担“所有原始采样”和“实际显示区间”两个语义。建议：

- source_samples：所有采集观察的 ID、UTC、采集区间与保留状态；有界、按段存储，不默认保存全部原始 RGB。
- samples/presentations：实际输出的显示区间、来源 source_sample_id、frame_uid，以及 resize/quantization 等变换信息。
- 输入事件保留 observed_sample_id，并另给 displayed_sample_id / frame_uid / offset。最近显示帧不是原始采样时，标记 nearest_retained；没有画面时标记 unmapped。
- 同一原始采样被分成多段停留区间时，允许多个 presentation 指向它，不生成假的新采样 ID。
- gif_fps 降低而丢弃的像素不能通过时间线恢复；metadata 留存不等于原始画面留存。只支持届时的当前 schema 3；不内置 schema 1/2 读取、迁移或猜测映射。
- 所有新增来源、epoch 和映射数据均计入时间线字节/条数预算；压力触发提前轮转，不能只把原来的容量上限翻倍。

浏览器可能把 10 毫秒帧延时改成更长时间。60 FPS 用于高频采样和支持相应时序的逐帧工具；面向 README/浏览器分享默认选 30 FPS。播放兼容性与捕获是否成功分开报告。

## 6. API、优先级与 AI 使用

建议配置优先级为：明确高级参数 > 明确 preset > 默认 demo。所有默认只在统一的配置解析器解析一次，CLI/MCP/GUI 不各自复制默认值。

新版接口直接删除 fps / max_width / quality，分别使用 capture_fps、gif_fps、size、quantizer_effort。遇到已删除参数明确报错，不提供别名、自动转换或兼容开关；当前尚未实施此接口切换。

建议增加无录屏副作用的 framelet_plan_recording：只检查参数、区域、预算和配置，返回请求/解析值、冲突、预计内存及建议。不能声称它实测了性能。真正的短时校准需要单独显式操作，采集画面必须先遮挡，校准结束销毁临时数据。

拟议 MCP 参数示例（不可作为当前命令执行）：

```json
{
  "preset": "demo",
  "size": {"mode": "native"},
  "colors": 256,
  "dither": "off",
  "palette_mode": "stable",
  "capture_fps": 60,
  "gif_fps": 30
}
```

解释：原尺寸采集 60 FPS，以 30 FPS 时间调度生成 GIF，侧车保留来源与显示关系。它不等于可以从 GIF 中抽取全部 60 FPS 原始画面。

所有预设默认 strict：开始前发现预算不符就给出具体建议；录制中负载变高时如实记录实际采集率/错过的采样期限，持续严重不足按既有故障合约停止/partial。自适应降级必须另行显式开启，第一阶段不实施。不能静默缩小 test/precision 的文字或减少颜色。

## 7. 架构、资源和恢复

```text
录制请求 → VisualConfigResolver → 校验/资源计划
采集 + 键鼠观察 → 掩码 → 空间变换 → 时间选择
    → 调色板映射/抖动 → 最终画布差分 → GIF writer
    → 来源/显示映射、质量统计 → 时间线/校验/检查点
```

建议新建 visual 模块：config.rs（参数/预设）、resize.rs、palette.rs、dither.rs、temporal.rs、metrics.rs。recording 与 series 共用这些服务，encode.rs 专注 GIF 结构和发布，不承担预设解析与 AI 场景推断。

- 原始采集像素率、缩放处理像素率、GIF 编码像素率分开计量。把 gif_fps 降为 1 不能掩盖全屏 60 FPS 的采集/缩放成本；max_width 也不一定减少 GDI 抓取前的成本。
- 保留现有输出像素、解码工作量和长录制预算；新模式重新计算全部阶段，校准后才能决定是否调整工程上限。
- 调色板统计采用有界抽样/直方图和有限缓存，不能为训练整段色表缓存 300 秒 RGB。
- 尺寸和算法更新在段边界提交。palette epoch 更新可在同段发生，必须完整关键帧和配置记录。
- 检查点包含解析配置、调色板/epoch、显示时序、原始到显示映射；先保证编码前缀和时间线一致，再提交检查点。恢复仅使用已验证数据，不重新量化旧段或猜测新参数。
- 队列满、分配/编码/写盘失败遵循当前结构化 failure、partial 与保留已提交段的合约，不在异常时偷偷切换到更宽录制区域。
- 当前先支持明确的 SDR 管线；HDR/色彩管理必须单独设计，不能把 HDR 字节当 SDR 直接量化。

质量报告只给可解释的测量：原/输出尺寸、实际采样率、输出调度率、编码帧数、源观察未输出数、palette epoch 数、抽样 RGB 误差及文件大小。没有校准前不推出主观“质量 97 分”。

## 8. 验收与实施顺序

1. 配置解析：四预设、覆盖优先级、互斥参数、非法值、单段/分段一致；已删除参数和非当前格式必须明确拒绝。
2. 像素：细字、代码、图标、棋盘格和非整数缩放；native 不进入重采样；遮挡不泄漏；坐标映射覆盖负屏幕坐标、DPI 与整数取整。
3. 颜色：32/64/128/256 色、简单色精确映射、渐变、暗色 UI、不同位置的变化矩形；静止图无闪烁；epoch 更新后完整合成正确；不能只看文件变小。
4. 时间与身份：60/60、60/30、30/12、1/1；Pillow 等独立解码核对时长；键鼠区分原始/显示帧；不能把 source_samples 当成可恢复 RGB。
5. 长录制：300 秒边界、600/650 秒、暂停、检查点、提前轮转、崩溃恢复；恢复前后颜色/时间映射一致，正常结束无临时段残留。
6. 真实场景：编辑器小字、表单、网页滚动、暗亮主题切换、渐变演示；同时比较可读性、稳定性、体积、CPU、内存和采样丢失。

建议拆三次交付：先配置解析/像素控制；再稳定调色板/颜色/抖动；最后独立时间控制与 schema 3。每步完成再更新 README，未实现参数只保留在设计文档。60 FPS 上限单独上线，不把它包装成上述整套策略已经完成。
